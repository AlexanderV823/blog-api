# REST API для блога на Go (Blog-API)

Промышленное REST API для блога с поддержкой JWT-авторизации, публикаций, комментариев, структурированного логирования, автоматических транзакционных миграций и многопоточного Rate Limiter. Проект спроектирован по принципам Чистой Архитектуры (Clean Architecture) с полной инверсией зависимостей через Go-интерфейсы.

В комплекте поставляется современный, модульный веб-интерфейс (SPA), полностью изолированный от бэкенд-логики.

## 🚀 Основные возможности

- **Аутентификация и Безопасность**:
  - Регистрация и вход с валидацией email стандартными средствами RFC (`net/mail`).
  - Строгая проверка сложности пароля (буквы + цифры) на уровне сервиса с возвратом понятной ошибки `400 Bad Request`.
  - Вход в систему с жестким разграничением легитимных (`401 Unauthorized`) и инфраструктурных (`500/503`) ошибок.
  - Генерация криптографически подписанных JWT-токенов (HS256) без использования небезопасных unverified-методов.
  - **Полноценная защита от Race Condition**: Конкурентные запросы регистрации перехватываются базой данных. Ошибка `unique_violation` (код `23505`) корректно извлекается из сложной цепочки слоев через `errors.As` и гарантированно мапится сервисом в статус `409 Conflict`, предотвращая утечку SQL-дескрипторов.
- **Управление публикациями и комментариями**:
  - Создание, чтение, строго валидированная пагинация, обновление и удаление.
  - Контроль прав доступа: изменять и удалять ресурсы может только их непосредственный автор (`403 Forbidden`).
  - Предварительная валидация внешних ключей в слое бизнес-логики: создание комментария к несуществующему посту перехватывается до обращения к БД и возвращает `404 Not Found`.
- **Строгая валидация и защита памяти (Харденинг Handler-слоя)**:
  - Ограничение размера входящего тела запроса через `http.MaxBytesReader` (защита от OOM и DoS атак).
  - Запрет неконтрактных и избыточных данных через `DisallowUnknownFields`.
  - Валидация JSON-потока на отсутствие лишних байт и вторых объектов после завершения валидной структуры.
  - Измерение длины строк исключительно в **рунах (UTF-8)** через `utf8.RuneCountInString`, что гарантирует корректный учет кириллицы, в отличие от байтового `len()`. Очистка внешних пробелов через `strings.TrimSpace`.
- **Инфраструктурные Middleware**:
  - `Recovery` — автоматический перехват паник для предотвращения падения сервера.
  - `RequestID` — генерация сквозного ID для трассировки цепочки логов.
  - `CORS` — гибкая настройка заголовков для работы с frontend-приложениями.
  - **Потокобезопасный RateLimiter**: Настоящий Token Bucket с раздельной атомарной блокировкой клиентов (`sync.Mutex`), вычислениями во `float64` без потери дробной части токенов и автоматической фоновой очисткой старых IP по TTL (защита от Memory Leak). Лимитер устойчив к спуфингу, так как работает на базе физического сетевого адреса `r.RemoteAddr`, а уязвимая legacy-реализация на `sync.Map` полностью удалена.
  - `Logger` — детальные логи запросов с подсчетом байт ответа и времени обработки.
- **База данных и Health Check**:
  - Автоматические транзакционные миграции схемы данных при старте сервиса из Go-кода методом `go:embed`.
  - Осмысленный (meaningful) `/api/health` эндпоинт: выполняет `PingContext` и тестовый легковесный `SELECT` к таблицам схемы с коротким тайм-аутом. Возвращает стабильное нейтральное сообщение без утечки сырых ошибок драйвера (`driver: bad connection`) во внешний JSON при сбое СУБД.

## 🛠 Технологический стек

- **Язык**: Go (Golang) 1.20+
- **HTTP Роутер**: [go-chi/v5](https://github.com/go-chi/chi/v5)
- **База данных**: PostgreSQL
- **Драйвер БД**: [lib/pq](https://github.com/lib/pq)
- **Конфигурация**: Environment Variables через [godotenv](https://github.com/joho/godotenv)
- **Фронтенд**: Чистый HTML5, Vanilla CSS (Custom Properties), Модульный JavaScript (ES6)
- **Контейнеризация**: Docker & Docker Compose

## 💻 Быстрый старт

### 1. Подготовка конфигурации
Перед запуском создайте файл `.env` в корневой папке проекта:

```env
# Настройки сервера Go
SERVER_PORT=8080
SERVER_HOST=0.0.0.0

# Настройки PostgreSQL для Docker и Go
DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=bloguser
DB_PASSWORD=blogpassword
DB_NAME=blogdb
DB_SSL_MODE=disable

# Безопасность (JWT)
JWT_SECRET=super-secure-random-secret-key-32-chars
JWT_EXPIRY_HOURS=24
```

### 2. Запуск приложения

#### Вариант А. Автоматизированный локальный запуск через `Makefile`
```bash
make dev
```
*Запустит контейнер базы данных, накатит миграции и поднимет безопасный Go-сервер с детектором гонок. Для плавной остановки нажмите `Ctrl+C`.*

#### Вариант Б. Полный запуск всего приложения в Docker контейнерах
Если вы хотите развернуть проект без локально установленного Go:
1. В файле `.env` укажите сетевое имя сервиса: `DB_HOST=postgres`.
2. Выполните команду сборки и старта:
   ```bash
   docker-compose up -d --build
   ```
3. Веб-интерфейс будет доступен по адресу: **`http://localhost:8080/`**, а СУБД-панель Adminer — по адресу **`http://localhost:8081/`**.

## 🧪 Тестирование и Метрики

### 1. Модульное и интеграционное тестирование (Unit Tests)
Проект покрыт unit-тестами с использованием легковесных тест-стабов и `sqlmock` без тяжелых генераторов кода. Тесты проверяют валидацию кириллицы, сложность пароля, обработку race-condition, работу JWT, логику миграций, пагинацию и поведение лимитера под нагрузкой.

Запуск тестов с детектором гонок:
```bash
make test
```

### 2. Определение покрытия проекта тестами (Code Coverage)
Для расчета честного сквозного покрытия кодовой базы и просмотра интерактивной карты выполнения строк (зеленый/красный) в браузере выполните:
```bash
make cover-html
```

### 3. Сквозное автоматизированное тестирование (E2E Integration Тесты)
В корне находится строгий тестовый сценарий `test_api.sh`. Он валидирует HTTP статус-коды, структуру JSON и контроль прав доступа (`403 Forbidden` при попытке модификации чужого контента).
```bash
./test_api.sh
```

## 🎯 Спецификация API и Правила Валидации

### Формат Ошибок
Все ошибки во всех обработчиках унифицированы и возвращаются строго в формате JSON с MIME-типом `application/json; charset=utf-8`. Инфраструктурные сбои СУБД полностью изолируются от внешнего клиента и переводятся в нейтральные `500/503` коды.
```json
{
  "error": "Описание ошибки для клиента"
}
```

### Основные эндпоинты

| Метод      | Эндпоинт                   | Права         | Ограничения и Валидация                                                                                                         |
| :--------- | :------------------------- | :------------ | :------------------------------------------------------------------------------------------------------------------------------ |
| **POST**   | `/api/register`            | Публичный     | Тело до 1 МБ. `username` (3-50 рун), `email` (RFC валидация), `password` (буквы + цифры, мин. 6 рун). Возвращает `201 Created`. |
| **POST**   | `/api/login`               | Публичный     | Тело до 1 МБ. Строгая проверка валидности. Разделение `401` и `500` кодов. Возвращает `200 OK` + JWT.                           |
| **GET**    | `/api/posts`               | Публичный     | Query: `limit` (число >0 до 100, по деф. 10), `offset` (число >=0). При ошибке формата — `400 Bad Request`.                     |
| **GET**    | `/api/posts/{id}`          | Публичный     | Поиск публикации по ID. При отсутствии — `404 Not Found`.                                                                       |
| **POST**   | `/api/posts`               | **JWT**       | Тело до 2 МБ. `title` (5-200 рун), `content` (10-50000 рун). Возвращает `201 Created`.                                          |
| **PUT**    | `/api/posts/{id}`          | **JWT Автор** | Обновление полей. Только для автора поста, иначе `403 Forbidden`. Возвращает `200 OK`.                                          |
| **DELETE** | `/api/posts/{id}`          | **JWT Автор** | Удаление публикации. Только для автора поста, иначе `403 Forbidden`. Возвращает `204 No Content`.                               |
| **POST**   | `/api/posts/{id}/comments` | **JWT**       | Тело до 256 КБ. `content` (1-2000 рун). Контроль существования родительского поста (`404`). Возвращает `201 Created`.           |
| **PUT**    | `/api/comments/{id}`       | **JWT Автор** | Редактирование текста комментария (1-2000 рун). Только для автора, иначе `403 Forbidden`. Возвращает `200 OK`.                  |
| **DELETE** | `/api/comments/{id}`       | **JWT Автор** | Удаление комментария. Только для автора, иначе `403 Forbidden`. Возвращает `204 No Content`.                                    |
| **GET**    | `/api/health`              | Публичный     | Проверка пула СУБД и состояния таблиц. Тайм-аут 2 сек. При аварии или пустой схеме — `503 Service Unavailable`.                 |
